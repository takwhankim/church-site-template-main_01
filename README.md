# 온맘교회 홈페이지 콘텐츠 관리

온맘교회 홈페이지와 TinaCMS 관리자 화면을 함께 관리하는 프로젝트입니다. 기존 페이퍼교회 프로젝트와는 별도입니다. 현재는 내 컴퓨터의 로컬 서버에서 홈페이지를 열고, TinaCloud에 연결된 GitHub 저장소의 콘텐츠를 읽는 방식입니다. 공개 호스팅과 도메인 연결이 완료된 상태를 뜻하지 않습니다.

## 홈페이지 실행

Node.js 22 이상이 필요합니다. 프로젝트 폴더에서 실행합니다.

```sh
npm start
```

- 홈페이지: <http://localhost:3000/>
- 관리자: <http://localhost:3000/admin/>
- 종료: 실행한 터미널에서 `Ctrl+C`

기본 실행은 `scripts/server.mjs`가 담당합니다. TinaCloud에서 저장하는 GitHub 저장소 `takwhankim/church-site-template-main_01`의 `main` 브랜치를 확인하고, 그 커밋의 `content/site.json`을 홈페이지에 제공합니다. 로컬 파일만 여는 방식이나 로컬 Git 작업 폴더를 자동으로 갱신하는 방식은 아닙니다. 클라우드 편집과 동기화에는 인터넷 연결이 필요합니다.

서버는 `127.0.0.1`에서 실행되므로 이 주소는 실행한 컴퓨터에서 사용합니다. 기본 포트는 `3000`이며 `PORT` 환경 변수로 바꿀 수 있습니다.

## 관리자에서 글과 사진 바꾸기

1. `/admin/`을 열고 TinaCloud 계정으로 로그인합니다. 해당 프로젝트와 저장소를 편집할 권한이 필요합니다.
2. `홈페이지 콘텐츠`에서 `site` 문서를 열고 원하는 항목을 수정합니다.
3. 사진은 해당 **사진 필드**를 눌러 미디어 창을 엽니다. 기존 사진을 선택하거나 새 사진을 업로드한 뒤 **Insert**로 필드에 넣습니다.
4. 필요한 사진 설명과 글 내용을 입력하고 문서의 **Save**를 눌러 저장 완료를 확인합니다. 사진 업로드와 Insert만으로 문서 수정까지 저장되는 것은 아닙니다.
5. 홈페이지로 돌아가 변경 내용을 확인합니다. 이미 열린 홈페이지도 화면이 보이는 동안 약 15초마다 콘텐츠를 다시 확인하며, 탭으로 돌아오거나 창에 포커스를 주어도 확인합니다. 글이나 사진의 상세 창이 열려 있으면 닫은 뒤 확인합니다.

예배 시간 목록에는 예배 이름, 설교와 게시글 목록에는 제목, 갤러리에는 사진 설명, 안내 버튼 목록에는 버튼 이름이 표시됩니다. 사진 필드 옆 안내를 따라 선택 → Insert → Save 순서로 저장하면 됩니다. 현재 편집은 관리자 폼에서 하고 홈페이지로 돌아가 결과를 확인하는 방식입니다. 홈페이지 화면의 요소를 직접 눌러 편집하는 기능은 연결되어 있지 않습니다.

서버에는 기본 10초 캐시가 있고, TinaCloud 저장 처리와 GitHub 반영·네트워크 요청에도 시간이 필요합니다. 따라서 저장 즉시 또는 15초 이내 반영을 보장하지 않습니다. 바로 보이지 않으면 잠시 기다린 뒤 홈페이지를 새로고침하고, 계속 보이지 않으면 관리자 저장 상태와 GitHub `main`의 변경 여부를 확인합니다.

편집할 수 있는 주요 항목은 다음과 같습니다.

- 교회 이름, 헤더·푸터 로고, 첫 화면 문구와 히어로 이미지
- 예배 안내와 예배 시간
- 설교 제목·날짜·본문 말씀·요약·YouTube 링크 (홈페이지 주요 설교 영역에는 목록의 첫 항목 표시)
- 교회 소식 게시글, 대표 사진, 추가 사진 갤러리와 사진 설명
- 주보 PDF 주소
- 새가족 안내, 주소·연락처·지도 링크
- 홈페이지 안내 메뉴 문구와 이동 버튼

콘텐츠는 `content/site.json`, 업로드한 사진은 `uploads/`에 저장됩니다. 홈페이지는 JSON을 읽은 **동일 GitHub 커밋**의 `uploads/` 주소로 사진을 불러와, 새 글과 이전 버전 사진이 섞이는 문제를 줄입니다. 외부 이미지 URL이나 외부 PDF는 해당 외부 서비스가 관리합니다.

## 인터넷 연결이 끊겼을 때

GitHub 동기화에 실패하면 서버 실행 중 마지막으로 정상 수신한 콘텐츠를 유지합니다. 아직 정상 수신한 콘텐츠가 없다면 프로젝트에 들어 있는 `content/site.json`과 `uploads/`를 로컬 백업으로 사용합니다. 마지막 정상 콘텐츠는 서버 메모리에만 있으므로 재시작 후에도 유지되는 별도 백업은 아닙니다.

브라우저의 갱신 요청이 실패하면 기존 화면을 유지합니다. 다만 마지막 정상 콘텐츠가 참조하는 GitHub 사진이나 외부 자료까지 오프라인으로 저장하는 기능은 없으므로, 연결이 끊긴 상태에서 모든 사진·영상·PDF가 표시되는 것은 보장하지 않습니다.

## 개발·빌드·검증

개발 명령에는 개발 의존성이 필요합니다. 처음 준비할 때 프로젝트 폴더에서 설치합니다.

```sh
npm install --include=dev
```

| 명령 | 동작 |
| --- | --- |
| `npm start` | GitHub `main` 콘텐츠를 동기화하는 로컬 홈페이지 서버 실행 |
| `npm run dev` | 같은 서버를 파일 변경 감지 모드로 실행 |
| `npm run cms` | TinaCMS **로컬 개발 모드**와 홈페이지 서버 실행. 홈페이지는 로컬 `content/site.json`을 읽음 |
| `npm run build` | `tina/config.ts`를 기준으로 `admin/` 관리자 화면 생성 |
| `npm test` | Node.js 테스트 실행 |

`npm run cms`에서 편집한 로컬 변경은 GitHub `main`에 자동으로 반영되지 않습니다. 클라우드 운영 편집은 기본 실행의 `/admin/`을 사용합니다. `npm run build`는 관리자 화면을 생성하는 명령이며, 공개 배포까지 수행하지 않습니다.

클라우드용 관리자 화면을 다시 빌드할 때는 기존 프로젝트에 맞는 환경 변수를 실행 환경에서 제공합니다.

- `NEXT_PUBLIC_TINA_CLIENT_ID`: TinaCloud 프로젝트 ID
- `TINA_TOKEN`: 해당 프로젝트의 읽기 토큰
- `GITHUB_BRANCH`: 관리자 편집 대상 브랜치, 기본값 `main`

토큰 값을 README, 소스 코드, Git 추적 파일에 직접 저장하지 않습니다. 현재 홈페이지 서버의 저장소와 브랜치는 `scripts/server.mjs`의 기본값을 사용합니다. `GITHUB_BRANCH`만 바꿔도 홈페이지 동기화 대상까지 바뀌는 것은 아니므로, 운영에서는 관리자와 홈페이지가 같은 저장소의 `main`을 바라보는지 확인해야 합니다.

## 공개 운영 전에 별도로 확인할 사항

- 공개 호스팅과 도메인 연결, 배포 방식 및 해당 환경에서의 콘텐츠 동기화
- 실제 교회 이름·주소·연락처·예배 시간·지도·설교·주보 등 운영 정보
- 헌금 안내의 실제 계좌 또는 결제 서비스 연결
- 새가족 등록 등 개인정보 접수의 저장·전송 기능과 운영 정책

현재 새가족 양식은 접수 내용을 저장하거나 전송하는 운영 시스템으로 연결되어 있지 않습니다. 헌금과 개인정보 접수는 별도 확인·연결이 필요한 항목이며, 홈페이지 안내 메뉴도 실제 상담 서비스와 연결된 챗봇은 아닙니다.
